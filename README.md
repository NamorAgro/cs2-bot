# Steam buyback bot: CS2, Rust and Dota 2

Бот работает одним постоянным процессом на DigitalOcean. Сайты на Vercel обращаются к его API через HTTPS-прокси. Бот принимает предметы пользователя; цены, балансы и холд рассчитывает сайт. Бот не выполняет денежные выплаты.

| `game` | Steam app ID | context ID |
| --- | --- | --- |
| `cs2` | 730 | 2 |
| `rust` | 252490 | 2 |
| `dota2` | 570 | 2 |

Запрос без `game` использует `cs2` для совместимости с прежними сайтами. Название игры указывается и в сообщении трейда.

## Окружение

- Node.js 22 LTS, версия 22.14 или новее в ветке 22; системный `curl`.
- `npm ci` для установки зависимостей.
- `.env` по образцу `.env.example`; встроенный `process.loadEnvFile` читает файл рядом с `bot.js`, независимо от рабочей директории процесса. Зависимость `dotenv` не нужна.
- Файл существующего Steam-аккаунта `lib/secrets/bot.maFile` с `account_name` и `shared_secret`.
- Порт `PORT` (по умолчанию 3002) слушает только `127.0.0.1`; внешний доступ — через HTTPS-прокси.

`npm run check:config` проверяет локальные настройки без входа в Steam и без сетевых запросов. `npm test` запускает автономные тесты с подменой Steam, HTTP и секретов. `npm start` выполняет настоящий вход в Steam и запускает API.

## Подключение магазинов

Существующий `BOT_API_KEY` сохранён: это клиент `legacy`, через который продолжают работать CS2/Rust. **При обновлении сервера оставьте его текущий ключ и пароль Steam.** Локальные значения не являются основанием заменять настройки работающего сервера.

Для Dota добавьте в серверный `.env`:

```dotenv
BOT_CLIENTS_JSON='[{"id":"dotaskin","apiKey":"SAME_AS_DOTA_STOREFRONT_BOT_API_KEY","games":["dota2"],"callbackOrigins":["https://www.dotaskin.io"]}]'
```

В `apiKey` нужен именно `BOT_API_KEY` Dota-магазина, а не ключ Waxpeer, Steam Web API или платёжной системы. В локальном `.env` Dota-клиент уже настроен по текущему окружению магазина; `.env` не публикуется в Git. Для других сайтов добавляйте записи с уникальными `id` и `apiKey`. Не переименовывайте `id`, пока у магазина остаются незавершённые трейды или уведомления.

Бот проверяет разрешённую игру и точный origin callback. Для Dota это `https://www.dotaskin.io`, включая `www`. Редиректы callback запрещены; адрес должен сразу отвечать без перенаправления. Ответы отправляются с ключом магазина, создавшего трейд.

Для прежнего общего ключа можно ограничить адреса через `BOT_CALLBACK_ORIGINS=https://www.cs-store.example,https://www.rust-store.example`. Без этого параметра сохраняется прежняя совместимость с несколькими сайтами; используйте общий ключ только на доверенных серверах. `API_BASE_URL` больше не требуется: старый код проверял его наличие, но фактически использовал адрес из запроса.

## Контракт API

Оба POST-метода требуют заголовок `x-bot-api-key` и JSON.

`/get-inventory`: `{ "steamId": "STEAM_ID_64", "game": "dota2" }`. Ответ: `{ "ok": true, "game": "dota2", "count": 1, "items": [...] }`. Поля предмета: `assetid`, `classid`, `market_hash_name`, `icon`. Возвращаются только передаваемые предметы нужной игры с рыночным названием. Загружаются все страницы до 5000 предметов; при превышении лимита возвращается ошибка вместо незаметного обрезания. Кэш на 30 секунд разделён по пользователю и игре.

`/create-offer`: `steamId`, `game`, `tradeUrl`, `assetids` (1–50 уникальных строк), `callbackUrl`. Steam trade URL должен принадлежать этому SteamID. Перед отправкой инвентарь перечитывается. У предметов проверяются app/context ID и возможность передачи. Из стека берётся **одна единица на asset ID**, поскольку сайт оценивает одну единицу. Ответ: `{ "ok": true, "offerId": "...", "status": "sent" }` (либо `pending`, если Steam требует подтверждения).

Новая заявка может отменить только прежние активные предложения выкупа того же пользователя, игры и магазина. Неизвестные предложения и предложения с предметами бота не отменяются. Одновременная отправка двух предложений из одного инвентаря блокируется. Если отмена прежнего предложения не удалась, новое не отправляется.

При потере ответа Steam возвращается HTTP 502 с неопределённым результатом. Это **не доказательство отсутствия трейда**: нельзя автоматически завершать заявку или повторно начислять деньги. Dota-магазин уже оставляет такие заявки ожидающими статуса. Бот не выполняет автоматическую повторную отправку трейда.

## Статусы и хранение

Callback: `POST /api/steam/offer-state-changed?requestId=...`, тело `{ "offerId": "...", "state": "ACCEPTED", "rawState": 3 }`. Поддерживаются `ACCEPTED`, `CANCELED`, `DECLINED`, `EXPIRED`, `ESCROW`. Получатель должен возвращать HTTP 2xx и `{ "ok": true }` и обрабатывать повторные уведомления идемпотентно. В текущих Dota/CS2/Rust-проектах зачисление защищено проверкой перехода состояния в транзакции.

- `offer-callbacks.json` хранит адрес, идентификатор магазина, игру и очередь недоставленных статусов. Старый формат с `callbackUrl` и `createdAt` читается как `legacy`. API-ключи в этот файл не записываются.
- Изменения сохраняются через временный файл и переименование. Повреждённое хранилище останавливает запуск, чтобы не потерять связи сделок с магазинами.
- Неуспешные уведомления повторяются с увеличением интервала до 5 минут и сохраняются после перезапуска. Не удаляйте файл и не меняйте рабочий каталог приложения при обновлении без переноса состояния.
- `savePollData` сохраняет историю отслеживания Steam и привязку нового предложения к магазину. Библиотека использует свой каталог данных учётной записи ОС; сохраняйте тот же системный аккаунт процесса и его каталог данных.
- Запускайте **один экземпляр бота**, не PM2 cluster: файловое хранилище и блокировки рассчитаны на один процесс.

Повторные уведомления обеспечивают доставку уже зарегистрированных событий. Результат отправки, при котором Steam не вернул ID, может требовать ручной сверки в Steam; очередь не заменяет такую сверку.

## Обновление DigitalOcean

1. Сохранить серверные `.env`, maFile, `offer-callbacks.json` и каталог данных Steam-библиотеки. Не добавлять их в Git.
2. Обновить `bot.js`, `lib/*.js`, `package.json`, lock-файл, скрипты и тесты. Старый маленький `dota2.patch` из storefront больше не нужен: поддержка уже находится в исходниках бота.
3. Проверить `node --version`, выполнить `npm ci`, добавить Dota-клиента, сохранив серверный legacy-ключ. Выполнить `npm run check:config` и `npm test`.
4. Перезапустить существующий сервис бота тем же пользователем ОС, с одним процессом. Проверить готовность Steam в журнале.
5. Согласованно проверить инвентарь Dota и один недорогой тестовый трейд. Убедиться, что статус пришёл на `www.dotaskin.io`, баланс в холде начислился один раз, повторный callback не меняет сумму. Затем проверить чтение инвентарей CS2/Rust.

Изменения подготовлены локально; установка на сервер и реальные трейды выполняются отдельно. В исходном репозитории уже отслеживается `node_modules`; `.gitignore` исключает новые локальные зависимости, но ранее отслеживаемые файлы автоматически не удаляет.

Справка библиотек: [TradeOffer.data и количество предметов](https://github.com/DoctorMcKay/node-steam-tradeoffer-manager/wiki/TradeOffer), [TradeOfferManager и savePollData](https://github.com/DoctorMcKay/node-steam-tradeoffer-manager/wiki/TradeOfferManager), [Node.js loadEnvFile](https://nodejs.org/docs/latest-v22.x/api/process.html#processloadenvfilepath).
